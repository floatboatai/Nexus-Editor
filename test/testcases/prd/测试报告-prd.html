BUG-001（核心数据流） 严重程度：中

关联用例FP-03-01-F02
所属模块packages/core/src/editor.ts · @codemirror/commands
现象CM6 history 合并相邻变更：带 userEvent:input.type 的 dispatch 与后续无 userEvent 的 setDocument 被合并为同一 undo 组，一次 undo 全部回退，混合 API 调用无法逐步 undo/redo。
影响范围所有通过 setDocument 修改文档的 API 场景（外部替换、文档加载、插件批量写入），undo 组边界错误

根因分析（源码证据链）

  1. editor.ts L427-437 performSetDocument 的 view.dispatch({ changes, annotations: silent ? silentDocChange.of(true) : undefined }) 未附加 isolateHistory 注解、也未附加 userEvent 注解（silent 只跳过 change 事件，不隔离历史）。
  2. @codemirror/commands dist L482-497 addChanges 合并规则：条件为 lastEvent.changes 非空 && 本次 event.changes 非空 && (!userEvent || joinableUserEvent.test(userEvent))。本次 setDocument 无 userEvent → !userEvent 恒为 true，直接放行合并。
  3. 再叠加时间条件 time - prevTime < newGroupDelay（默认 500ms）与 isAdjacent（变更边界相接）。setDocument 整文档替换 from:0 与上一个 input.type 变更边界相邻；测试中两次 dispatch 在同一同步块内，时间差必然 < 500ms。
  4. 合并分支用 event.changes.compose(lastEvent.changes) 拼成单个 HistEvent → 一次 undo 同时回退用户输入与 setDocument 替换。

修复建议

  1. performSetDocument 的 dispatch 附加 isolateHistory.of(true)（从 @codemirror/commands 引入），强制 setDocument 变更自成独立 undo 组；
  2. 或为 dispatch 附加 userEvent: 'setDocument'（不匹配 /^(input\.type|delete)($|\.)/，addChanges 走 else 分支新建事件组）；
  3. silent 文档加载场景同样建议隔离（避免载入文件后 undo 把整个文件清空）。

BUG-001（LivePreview） 严重程度：中

关联用例FP-04-03-E01
所属模块packages/core/src/live-preview.ts · @codemirror/view
现象createWidget 每次调用创建匿名类，CM6 WidgetType.compare 的 constructor 检查短路导致 eq() 永不调用，自定义 renderer 的 widget DOM 在每次光标移动时被重新挂载，DOM 状态丢失。
影响范围livePreview 自定义 renderer widget（代码折叠等）在光标移动时的 DOM 稳定性；eqKey 设计意图完全失效

根因分析（源码证据链）

  1. live-preview.ts L110 createWidget 返回 new (class extends WidgetType {...})() —— 每次调用都生成全新的匿名类；L112 注释明确 'Stable identity used by eq() so CM6 reuses old DOM across rebuilds'，即 eqKey 复用是设计意图。
  2. @codemirror/view dist L139-141 WidgetType.compare(other) = this == other || this.constructor == other.constructor && this.eq(other)。匿名类导致每次 constructor 不同 → constructor 短路 → eq() 永不调用。
  3. @codemirror/view dist L2525-2552 findWidget 双 pass：pass0 用 compare（constructor 不同 → false）；pass1 要求 tile.widget.constructor == widget.constructor 且 updateDOM() 返回 true。自定义 renderer 未实现 updateDOM（WidgetType 默认返回 false）→ 返回 null。
  4. 结果：旧 widget 的 DOM 无法复用 → 走 WidgetTile.of(widget) 重新 toDOM() 构建 → 光标每次移入/移出 widget 范围，DOM 全部重建，表单状态等丢失。

修复建议

  1. 将匿名类改为具名类（如 class RendererWidget extends WidgetType），同一 nodeType 的所有实例共享同一 constructor，使 compare 的 constructor 检查通过、eq() 得以调用，eqKey 复用生效；
  2. 或按 nodeType 缓存类定义（const Cls = class extends WidgetType {...} 提到模块级），避免每次 createWidget 重新创建类；
  3. 若需极端性能可额外实现 updateDOM 支持 pass1 的原地 DOM 更新。
