## 重要发现

### J01. CM6 undo 分组：空格/换行是独立 undo 组

- **发现来源**：FP-14-01-N02 / FP-14-01-N06
- **发现类型**：操作技巧
- **现象描述**：`typeInEditor("one")` 后再按 `Space`/`Enter`，撤销一次只能回退到 `"one"`（空格/换行单独成组），无法一次撤销回空文档。
- **解决方案**：多步输入时将空格/换行直接并入字符串（`"one "`、`"line1\n"`），使整个输入成为一个 undo 组。
- **影响范围**：所有涉及"输入后撤销到初始状态"的用例。

### J02. 共享编辑器实例导致 undo 栈污染

- **发现来源**：FP-14-01-N09 / FP-14-01-N12
- **发现类型**：状态验证
- **现象描述**：共享同一 editor 实例时，`clearEditor`（Ctrl+a+Backspace）本身也进入 undo 栈，下一条用例按一次 Mod-z 会先撤销清除操作，导致断言失败。
- **解决方案**：改用 `page.reload()` 获得全新编辑器实例，彻底隔离 undo 栈。
- **影响范围**：同一 spec 文件内多条用例之间。

### J03. typeInEditor 的 click 会破坏已建立的键盘选区

- **发现来源**：FP-14-01-N10 / FP-14-01-N09 / FP-14-02-N08
- **发现类型**：操作技巧
- **现象描述**：`typeInEditor` 内部 `page.click(".cm-content")` 会把光标移到点击处（通常是文末），破坏之前用 `Shift+ArrowRight` 建立的选区，导致覆盖/替换类操作在错误位置生效。
- **解决方案**：选区建立后一律用 `page.keyboard.type()` 直接输入，不再经过 typeInEditor。
- **影响范围**：所有替换选区文本的用例。

### J04. macOS 上 Mod-y 被 CM6 mac 配置覆盖

- **发现来源**：FP-14-02-N03 / FP-14-02-N11
- **发现类型**：与预期不符
- **现象描述**：CM6 historyKeymap 定义 `{key:"Mod-y", mac:"Mod-Shift-z", run:redo}`，macOS 上 Mod-y 实际不绑定 redo，而是被 mac 字段覆盖为 Mod-Shift-z。
- **解决方案**：N03 改为验证"macOS 上 Cmd+y 不触发 redo"这一平台预期行为；N11 改为 Mod-Shift-z 连续重做。
- **影响范围**：快捷键类用例需按平台调整预期。

### J05. CM6 Delete 后光标停留在删除位置

- **发现来源**：FP-14-01-N09
- **发现类型**：与预期不符
- **现象描述**：输入 "ABC" → Home → ArrowRight（光标在 B 前）→ Delete 删除 B 后，光标停留在 `A|C`，继续输入 X 得 `AXC`。用例文档预期 `ACX`（假设删除后光标跳到文末）与 CM6 真实语义不符。
- **解决方案**：修正断言为 `AXC`。撤销 X 后仍恢复 `AC`、撤销 Delete 后仍恢复 `ABC`，测试意图（撤销栈行为）不受影响。
- **影响范围**：涉及"删除后继续输入"的断言编写。

## 额外教训

## FP-14-01 / FP-14-02 额外教训

### E01. 根 config 的 testDir 限制导致 CASE 级 spec 无法运行

- **发现来源**：运行器调试
- **发现类型**：操作技巧
- **现象描述**：项目根 `playwright.config.ts` 的 `testDir: ./test/e2e` 会拒绝运行 CASE 目录下的 spec。
- **解决方案**：在 CASE 目录创建独立 `playwright.config.ts`（`testDir: "./"` + `testMatch: /RUN-.*\.spec\.ts$/`），并在 CASE 目录内运行。
- **影响范围**：所有 CASE 级 e2e 执行。

### E02. runner JSON 解析：用 indexOf("{") 而非 lastIndexOf("{")

- **发现来源**：阶段4.1 批量回归
- **发现类型**：运行器
- **现象描述**：`--reporter=json` 输出为 pretty-print 多行 JSON，且 `2>&1` 会把 npm warn 混入 stdout 开头。用 `lastIndexOf("{")` 截取会落到 JSON 末尾某个对象上导致解析失败。
- **解决方案**：改用 `stdout.indexOf("{")` 从第一个 `{` 开始解析。
- **影响范围**：runner 批量回归。

### E03. runner 对 playwright 结果的判定字段

- **发现来源**：阶段4.1 批量回归
- **发现类型**：运行器
- **现象描述**：`json.suites[0].failures` 字段在 JSON reporter 中不存在，永远判定为通过。
- **解决方案**：改为基于 `json.stats.unexpected === 0` 判定，`expected`/`unexpected`/`duration` 从 stats 取。
- **影响范围**：runner 批量回归结果可信度。
