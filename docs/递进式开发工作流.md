# 递进式开发工作流

> 适用范围：`f:\AiAutoCode\A4-finished-Item\MarkdownEditor\Nexus-Editor`
>
> 目的：通过小步提交、文档同步、分支推送，降低开发风险，提高可恢复性。

---

## 一、核心原则

1. **一个功能一个分支**
2. **一个阶段一个 commit**
3. **每次 commit 前更新进度文档**
4. **每次 commit 后立即推送到云端**
5. **测试全绿才能提交**

---

## 二、分支命名

遵循项目 Conventional Commits 与分支规范：

```
<type>/<scope>-<short-desc>
```

示例：

- `feat/search-fuzzy-support`
- `fix/search-regex-escape`
- `docs/roadmap-update`

---

## 三、开发阶段模板

每个功能拆分为以下阶段，每个阶段结束必须 commit + push：

| 阶段 | 任务 | 输出物 | commit 示例 |
|---|---|---|---|
| P0 | 计划与文档 | `docs/ai-dev-docs/*-开发计划.md` | `docs(search): add fuzzy search development plan` |
| P1 | 核心算法/数据结构 | 新文件 + 单元测试 | `feat(search): add fuzzy match algorithm` |
| P2 | 集成到现有系统 | 修改入口文件 + 集成测试 | `feat(search): integrate fuzzy option into search plugin` |
| P3 | 文档与示例更新 | README / 开发计划更新 | `docs(search): update README and progress doc` |
| P4 | 回归验证 | 全量测试通过 | `test(search): add regression tests for fuzzy search` |
| P5 | 最终整理 | PR 描述、清理无用代码 | `chore(search): clean up and finalize` |

---

## 四、提交前 checklist

每次 commit 前必须完成：

- [ ] 代码符合 TypeScript strict 要求
- [ ] 新增公共 API 有类型签名
- [ ] 新增功能有单测覆盖
- [ ] `pnpm test` 全绿
- [ ] `pnpm build` 成功
- [ ] `pnpm typecheck` 通过
- [ ] 进度文档已更新
- [ ] 不提交 `dist/`、`.env`、构建产物

---

## 五、推送策略

```bash
# 每次 commit 后立即推送
git push -u origin <branch-name>

# 后续小修改直接 push
git push
```

禁止：

- `git push --force` 到任何共享分支
- 在功能未验证前合并到 `main`
- 一个 commit 混合多个独立功能

---

## 六、进度文档维护

每个功能在 `docs/ai-dev-docs/` 下维护一份开发计划文档，结构：

```markdown
# 功能开发计划

## 目标
## 阶段划分
## 当前进度
## 已完成
## 待完成
## 风险与问题
## 验证结果
```

每次阶段推进后，更新「当前进度」和「已完成/待完成」列表。

---

## 七、恢复与回滚

如果需要回滚到上一个稳定阶段：

```bash
# 查看历史
git log --oneline

# 软回滚到某个阶段（保留工作区改动）
git reset --soft HEAD~1

# 硬回滚（慎用）
git reset --hard <commit-hash>
```

因为每个阶段都已推送到云端，可以通过 `git reflog` 或远程分支恢复。

---

## 八、PR 提交流程

功能完成后：

1. 确认全量测试通过
2. 更新开发计划文档为「已完成」
3. 在 GitHub 发起 Pull Request
4. PR 标题遵循 Conventional Commits
5. PR 描述说明 Why / What / 测试覆盖
6. 等待 review，不自行合并
